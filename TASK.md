Твоя задача - реализовать функционал записи gps трека и сопутствующих этому процессу экранов. Функционал реализуется в виде контекста src\recording\RecordingContext.jsx. Экраны 1) src\components\screens\RecordStartScreen.jsx и src\components\screens\RecordControlScreen.jsx (соответвуют экранам прототипа Record a route) (React 19 + Vite) . Кроме этих экранов можно изменять языковые файлы, относящиеся к этому экрану в src\locales.  Остальные файлы и экраны без необходимости не трогай, они будут правиться отдельной задачей потом. 
У тебя есть работающий на чистом js прототип tmp\girlpeak-prototype.html, его экраны "Record a route" соответствует экранам RecordStartScreen и RecordControlScreen, который тебе надо сдлеать по его образцу. 
Режим записи. Исправь контекст src\recording\RecordingContext.jsx для работы в режиме офлайн, для этого:
1) используй библиотеку Dexie для сохранения точек трека на локальном устройстве (батчами по 10–50 штук). 
2) измени apiFetch в src\api\client.js Для POST/PUT/PATCH при офлайне  писать задачу в Dexie а не пытаться сделать fetch. Для GET-запросов (открытие экранов): Используйте Service Worker (через vite-plugin-pwa). Он закэширует ответы API, и при офлайне экраны будут показывать последние загруженные данные.
После окончания записи открывай экран  src\components\screens\AddRouteScreen.jsx в который передавай записанный gpx трек и генерируй название, например Recorded at date/time. Так, чтобы пользователь мог одним нажатием кнопки сохранить записанный трек в виде маршрута. При создании маршрута теперь добавляй к полям источник source - в данном случае recorded. В src\components\screens\AddRouteScreen.jsx для других источников передавай поле source из списка enum, смотри протокол. Для справки:
drawn	Пользователь нарисовал маршрут на карте вручную (точки/линия)
gpx	Загружен GPX-файл (трек из другого приложения)
recorded	Записан в реальном времени (трекер, «я шёл, приложение писало»)
curated	создан пользователем с ролью admin
library	Из библиотеки (общего каталога маршрутов)
Взаимодействие с бэком. Используй src\api\client.js apiFetch. Ищи протоколы ендпойнтов в файлах api_routes.md, api.md. Не делай запросы к бэку, не тестируй, т.к. он может не работать. Следуй протоколу, описанному для этого экранав api.md
